1. Business Purpose

Project background
Lumia는 감정 회고와 커뮤니티 기능을 결합한 모바일 중심 서비스이다. 이 백엔드는 회원가입, 로그인, 토큰 재발급, 사용자 프로필 관리, 알림 설정, 정기 질문 제공, 추가 질문 제공, 답변 저장, 상점 구매, 게시글/댓글 관리, AI 채팅 기능을 담당한다.

Motivation
일반 메모 앱이나 일기 앱은 사용자가 매일 감정을 돌아보도록 유도하는 구조가 약하고, 지속적으로 사용하게 만드는 장치도 부족하다. Lumia는 질문 기반 감정 기록, 답변 이력 관리, 커뮤니티 소통, 코인과 아이템 보상, 캐릭터 성장 요소를 결합하여 이러한 한계를 보완하려는 목적을 가진다.

Goal
- 사용자가 질문을 통해 자신의 감정과 생각을 매일 점검할 수 있도록 지원한다.
- 사용자의 답변과 설정을 안전하게 저장하고 관리한다.
- 코인, 아이템, 캐릭터 레벨을 통해 지속적인 사용 동기를 제공한다.
- 게시글과 댓글을 통해 사용자 간 경험 공유를 지원한다.
- 백엔드에서 OpenAI를 호출하는 AI 채팅 기능을 제공한다.

Target market
- 짧은 질문 기반 자기 성찰을 원하는 사용자
- 감정 기록을 부담 없이 지속하고 싶은 모바일 사용자
- 개인 기록과 커뮤니티 소통을 함께 원하는 사용자

Description of terms
- Guest: 아직 로그인하지 않은 사용자이다. 일부 공개 조회 기능만 사용할 수 있다.
- Member: 로그인한 사용자이다. 질문, 답변, 상점, 프로필, 커뮤니티, 채팅 기능을 사용할 수 있다.
- Frontend Mobile App: 사용자가 실제로 사용하는 앱이며, 백엔드 API를 호출하고 결과를 화면에 표시한다.
- Lumia Backend System: 본 프로젝트의 핵심 시스템이다. 인증, 비즈니스 로직, 데이터 저장, 외부 연동을 처리한다.
- MariaDB: 사용자, 설정, 질문, 답변, 리프레시 토큰, 게시글, 댓글 등을 저장하는 데이터베이스이다.
- OpenAI Chat API: `/api/chat/completions` 요청 처리 시 백엔드가 호출하는 외부 AI 서비스이다.
- FastAPI Filter: 게시글과 댓글 작성/수정 전에 부적절한 내용을 검사하는 외부 필터링 서비스이다.

5. Problem Statement

Problem to be solved
- 사용자가 매일 자신의 감정 상태를 점검할 수 있는 구조화된 질문 시스템이 필요하다.
- 단순 기록 기능만으로는 사용 지속성이 낮기 때문에 보상과 성장 요소가 필요하다.
- 커뮤니티 기능은 악성/부적절 콘텐츠에 노출될 가능성이 있어 필터링이 필요하다.
- AI 기능을 프론트에 연결하되 비밀키는 반드시 백엔드에서만 관리해야 한다.
- 질문 발급, 답변 저장, 코인 차감 및 보상 처리가 사용자 단위로 일관성 있게 동작해야 한다.

Technical difficulties
- JWT access token 및 refresh token 기반 인증 흐름을 안전하게 관리해야 한다.
- 회원가입과 계정 변경 시 비밀번호 암호화와 중복 검증이 필요하다.
- 정기 질문이 하루에 중복 발급되지 않도록 시간 조건과 마지막 발급 기록을 정확히 처리해야 한다.
- 추가 질문은 하루 1회 제한을 지켜야 한다.
- 답변 저장, 코인 증가/차감, 아이템 구매, 캐릭터 레벨 증가가 트랜잭션 단위로 일관되게 처리되어야 한다.
- 게시글/댓글 수정 및 삭제는 작성자 권한 검증이 필요하다.
- FastAPI 필터 서버와 OpenAI API 같은 외부 시스템 장애에 대한 예외 처리가 필요하다.
- OpenAI 호출 시 타임아웃, 연결 실패, 응답 파싱 실패를 고려해야 한다.
- 개발 환경에서는 Java 17, Gradle, MariaDB, 환경변수 관리가 일관되게 맞아야 한다.

Non-Functional Requirements
- Security: 비밀번호는 암호화되어야 하며 JWT 검증이 정확해야 하고 OpenAI API 키는 백엔드에만 존재해야 한다.
- Availability: 핵심 기능은 안정적으로 제공되어야 하며 외부 연동 실패 시에도 적절한 오류 응답을 반환해야 한다.
- Reliability: 질문 발급, 답변 저장, 상점 구매, 토큰 재발급이 예측 가능한 결과를 반환해야 한다.
- Performance: 모바일 앱 사용성을 위해 일반 API 응답은 빠르게 처리되어야 하며 외부 API에는 타임아웃이 설정되어야 한다.
- Maintainability: controller, service, repository, dto, entity, config, security 계층 구조를 유지해야 한다.
- Scalability: 사용자 수, 게시글 수, 댓글 수, 채팅 요청 수 증가에 대응할 수 있어야 한다.
- Usability: 프론트가 처리하기 쉬운 명확한 성공/실패 응답 형식을 제공해야 한다.
- Data Integrity: 코인은 음수가 되면 안 되고, 중복 계정 정보와 무권한 수정/삭제는 차단되어야 한다.
- Interoperability: 모바일 앱, MariaDB, FastAPI 필터, OpenAI와의 연동이 일관된 데이터 형식으로 동작해야 한다.

6. Glossary

- Access Token: API 요청 인증에 사용하는 짧은 수명의 JWT이다.
- Refresh Token: access token이 만료되었을 때 새 access token 발급에 사용하는 토큰이다.
- JWT: 상태 비저장 인증을 위한 JSON Web Token이다.
- User Setting: 사용자별 알림 시간, 알림 주기, 질문 발급 이력을 담는 설정 정보이다.
- Scheduled Question: 사용자가 설정한 시간에 맞추어 제공되는 정기 질문이다.
- On-Demand Question: 사용자가 직접 요청하는 추가 질문이며 하루 1회만 허용된다.
- Answer Record: 사용자와 질문이 연결된 답변 저장 기록이다.
- Coin: 상점 구매에 사용하는 앱 내 재화이다.
- Purchased Item: 사용자가 이미 구매한 아이템이다.
- Equipped Item: 현재 사용자 프로필 또는 캐릭터에 적용된 아이템이다.
- Character Level: 답변 참여 등에 따라 성장하는 캐릭터 단계이다.
- Post: 커뮤니티 게시판에 작성되는 글이다.
- Comment: 게시글에 달리는 댓글이다.
- Moderation API: 게시글과 댓글 내용을 검사하는 외부 FastAPI 필터 서비스이다.
- AI Chat API: 백엔드가 OpenAI를 호출해 사용자 채팅에 대한 답변을 반환하는 API이다.
- MariaDB: 본 프로젝트에서 사용하는 관계형 데이터베이스이다.
